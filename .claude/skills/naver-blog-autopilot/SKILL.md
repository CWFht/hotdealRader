# 네이버 블로그 오토파일럿

주제(또는 브랜드커넥트 상품)를 받으면 **질문 없이 끝까지** 진행해서, 사용자가 훑어보고 거의 그대로 발행할 수 있는 패키지를 만든다. 사용자가 원하는 것은 "초안"이 아니라 "발행 직전 상태"다. 그래서 판단이 필요한 지점은 묻지 말고 스스로 정한 뒤, 무엇을 왜 그렇게 정했는지와 사람이 꼭 확인해야 할 것만 마지막에 짧게 알린다.

목표는 세 가지를 한 글에서 같이 잡는 것이다: **검색 상위노출**, **애드포스트 수익**, **브랜드커넥트 판매**. 셋은 따로 노는 목표가 아니라 한 줄로 이어진다. 검색 의도를 정확히 해결한 글이 노출되고, 노출된 글에 오래 머무는 독자가 광고 수익을 만들고, 그 글을 믿게 된 독자가 링크를 누른다. 그래서 어느 단계에서든 "독자에게 실제로 도움이 되는가"를 먼저 맞추고, 수익 장치는 그 위에 얹는다.

## 이 봇이 지키는 세 가지 원칙

9만 뷰 글을 만든 21년차 블로거의 인사이트에서 가져온 것으로, 모든 단계의 판단 기준이 된다.

1. **글 하나로 궁금증 두 개를 푼다.** 메인 키워드에 연결 키워드를 하나 붙여 나만의 주제로 만든다(예: "열품타 사용법" → "열품타 애플워치 연동 사용법"). 경쟁 글보다 가치가 하나 더 있고, 그 자체가 차별점이 된다.
2. **검색한 이유를 글 안에서 끝낸다.** 독자가 쓰는 말로, 독자가 필요한 정보를 담아 읽고 나서 의문이 남지 않게 한다. 체류 시간은 그 결과로 따라온다.
3. **제목에서 얻을 가치를 보여 준다.** 클릭하면 무엇을 얻는지 제목만 보고 예측되어야 한다. 숫자, 방법, 대상이 드러나는 제목이 기본이다.

## 입력

| 항목 | 없을 때 |
| --- | --- |
| 주제 또는 키워드 | 프로필의 주제 기둥에서 지금 쓸 만한 주제를 스스로 골라 진행하고, 고른 이유를 결과에 적는다 |
| 블로그 프로필 | `profiles/`에 프로필이 하나면 그것을, 여럿이면 주제에 맞는 것을 고른다. 맞는 것이 없으면 `_template.md` 기본값으로 쓰고 결과에 알린다 |
| 글 종류 | 상품 링크·캠페인 정보가 있으면 `brandconnect`, 아니면 `info` |
| 브랜드커넥트 정보 | 상품명, 제휴 링크, 캠페인 조건(필수 키워드·금지 표현 등). **링크는 받은 것만 쓴다.** 없으면 `[제휴 링크 삽입]` 자리로 남기고 검수 포인트에 적는다 |
| 경험 메모 | 사용자가 직접 겪은 일을 적어 줬을 때만 1인칭 경험으로 쓴다. 없으면 경험 문장을 쓰지 않는다 |

## 작업 순서

각 단계에서 읽을 참고 문서가 정해져 있다. 해당 단계에 들어갈 때 읽는다.

### 1. 프로필 읽기
`profiles/<블로그>.md`를 읽는다. 필자 말투, 분량, 마무리 형식, 이미지 스타일이 여기서 정해지고, 이 스킬의 일반 규칙과 다르면 **프로필이 우선**한다.

### 2. 키워드와 검색 의도 설계 → `references/naver-seo.md`, `references/monetization.md`
- 웹 검색으로 그 주제를 사람들이 실제로 어떤 말로 찾는지(자동완성·연관 검색어·질문형 검색), 지금 상위 글이 무엇을 다루고 무엇을 빠뜨렸는지 본다.
- 메인 키워드 1개 + 연결 키워드 1개(원칙 1) + 보조 키워드 2~3개를 정한다.
- 독자가 이 검색어를 친 이유를 한 문장으로 적고, 읽고 나서 생길 후속 질문 3~5개를 뽑는다. 이 질문들이 소제목의 재료다.
- 이 글이 수익 구조에서 맡을 역할(유입 글 / 비교·결정 글 / 구매 글)을 정한다. 역할에 따라 구성과 링크 배치가 달라진다.
- 검색량은 조회하지 못했으면 추정해서 단정하지 않는다.

### 3. 사실 확인
가격, 사양, 출시일, 조건, 메뉴 경로는 제조사·공공기관·공식 스토어에서 확인하고 출처를 남긴다. 확인하지 못한 것은 본문에서 범위를 좁혀 쓰고 검수 포인트의 '확인 필요'에 올린다. 발행 직전 수준을 목표로 하므로, 틀릴 수 있는 숫자를 그럴듯하게 채우는 것이 가장 큰 실패다.

### 4. 원고 작성 → `references/human-voice.md`, 브랜드커넥트면 `references/brand-connect.md`
- 원고는 `posts/<YYYY-MM-DD>_<짧은주제>/원고.md`에 아래 "원고 파일 형식"으로 저장한다.
- 도입 3줄 안에 독자 질문의 답을 준다. 소제목은 2단계의 후속 질문 순서대로 3~5개.
- 비교는 표로, 절차는 번호로 쓴다.
- 본문 흐름에서 한 발 떨어진 정보는 **곁들임 박스**로 뺀다(글당 1~3개): 놓치면 손해 보는 것은 `[주의]`, 알면 편한 것은 `[팁]`, 기준 날짜·출처·예외는 `[참고]`, 긴 절의 핵심은 `[요약]`. 본문 문장을 그대로 되풀이하는 박스는 만들지 않는다.
- 독자가 신청·조회하러 가야 할 **공식 페이지**가 있으면 `🌐 바로가기` 줄로 1~2곳 넣는다. 검색해서 다시 찾게 하지 않는 것이 "검색한 이유를 글 안에서 끝낸다"의 마지막 단계다. 주소는 확인한 공식 주소만 쓴다.
- 제목 후보는 각도를 달리해 3개(검색형·질문형·결론형)를 만들고 추천안을 `title`에 넣는다.

### 5. 사람 글로 다듬기 → `references/human-voice.md`
초고를 쓴 뒤 한 번 더 읽으며 AI 글 신호를 걷어낸다. 초고와 퇴고를 분리하는 이유는, 쓰는 동안에는 자기 말버릇이 보이지 않기 때문이다.

### 6. 이미지 → `references/images.md`
이미지마다 가장 맞는 방식을 스스로 고른다: 글자가 정확해야 하는 것은 **디자인 카드**(스크립트로 렌더링), 분위기·상황 컷은 **GPT 이미지**(프롬프트 작성, API 키가 있으면 바로 생성), 실물은 **공식 제품 이미지·직접 찍은 사진 자리**. 본문에는 `📷 이미지 01 │ 설명` 마커를 넣고 번호를 파일과 일치시킨다.

### 7. 검수와 패키징 (스크립트)
```bash
python scripts/check_post.py posts/<폴더>/원고.md            # 분량·키워드·AI 표현·대가성 문구 등 검수
python scripts/render_cards.py posts/<폴더>/cards.json        # 디자인 카드 PNG
python scripts/gpt_images.py posts/<폴더>/gpt_images.json     # GPT 프롬프트 파일(+키 있으면 생성)
python scripts/apply_frame.py posts/<폴더>/images --frame profiles/<블로그>.frame.json   # 프레임·도장 (프레임 있는 프로필)
python scripts/build_paste_html.py posts/<폴더>/원고.md       # 스마트에디터 붙여넣기용 HTML
python scripts/image_plan.py posts/<폴더>/원고.md             # 이미지 구성 표 + 한 장 미리보기
```
`check_post.py`가 `FAIL`을 내면 원고를 고치고 다시 돌린다. `WARN`은 읽고 판단하되, 남겨 두는 것은 이유를 검수 포인트에 적는다. 글자 수와 키워드 횟수는 눈대중이 아니라 이 스크립트의 계산값만 쓴다.

### 8. 브라우저 도구가 있으면 (선택) → `references/browser.md`
사용자의 로그인된 브라우저를 조작하는 도구(Aside MCP, Claude in Chrome 등)가 세션에 있으면 검색량 조회, 공식 페이지 확인, ChatGPT 이미지 생성, 스마트에디터에 올려 **임시저장**까지 대신한다. 발행은 하지 않는다. 도구가 없으면 건너뛴다.

### 9. 납품
파일을 사용자에게 보내고(파일 전송 도구가 있으면 사용. 붙여넣기용 HTML과 이미지 구성 미리보기는 내려받지 않아도 앱 안에서 바로 보이도록 `display: render`로, ZIP 패키지는 따로 보낸다) 채팅에는 아래만 짧게 쓴다. 긴 과정 설명은 검수를 방해한다.

```
제목: <추천 제목>  (다른 후보 2개)
키워드: 메인 / 연결 / 보조
이 글의 역할: 유입 글 | 비교·결정 글 | 구매 글, 다음에 이어 쓸 글 1~2개
검수 결과: 글자 수, 메인 키워드 횟수, 이미지 수 (스크립트 값)
이미지 구성: image_plan.py가 출력한 표 전체 (번호, 넣을 자리, 장면, 제작 방식, 상태, 파일)
사람이 확인할 것 (최대 5개): 확인 필요 사실, 넣어야 할 실물 사진, 제휴 링크 등
발행 순서: ① 제목 복사 → ② 본문 복사·붙여넣기 → ③ 이미지 마커 자리에 파일 삽입 → ④ 태그 입력
출처: 자료명 + 링크
```

**이미지 구성은 매번 보여 준다.** 글만 고쳤거나 이미지를 일부만 만든 경우에도 납품할 때마다 이미지 구성 표를 채팅에 넣고 `이미지구성_미리보기.png`를 함께 보낸다. 사용자는 이 표로 어떤 이미지가 어디에 들어가고 무엇을 직접 준비해야 하는지 판단하기 때문에, "이미지 7장" 같은 요약으로 줄이지 않는다.

## 원고 파일 형식

스크립트들이 이 형식을 읽는다.

```markdown
---
title: 열품타 애플워치 연동 방법 3단계, 공부시간 자동 기록까지
title_candidates:
  - 열품타 애플워치 연동이 안 될 때 확인할 3가지
  - 애플워치로 열품타 쓰면 뭐가 달라질까
main_keyword: 열품타 애플워치
sub_keywords: [열품타 사용법, 공부시간 기록]
type: info                 # info | brandconnect
profile: gajeonnampyeon
length: [1400, 1800]       # 공백 제외 글자 수 범위. 생략하면 기본값
closing_heading: 그래서, 제 결론은요   # 프로필이 정한 마무리 소제목. 없으면 생략
tags: [열품타, 애플워치, 공부앱]
experience: false          # 사용자가 준 경험 메모가 있을 때만 true
disclosure: ""             # brandconnect일 때 대가성 문구 원문
---

도입 문단...

[목차]

---

## 소제목

본문 문단. **핵심만 굵게.**

📷 이미지 01 │ 연동 설정 화면 요약 카드

| 구분 | A | B |
| --- | --- | --- |
| ... | ... | ... |

> [주의] 결제카드를 등록하지 않으면 충전기에서 결제되지 않아요.

🌐 바로가기 │ 무공해차 통합누리집 │ https://ev.or.kr

🔗 링크 │ 상품명 │ https://...
```

- `[목차]`는 스크립트가 소제목으로 채운다.
- 본문 표는 붙여넣기 파일에서 항상 본문 폭 100%, 열 너비 균등으로 고정된다. 열마다 글자 길이가 크게 다르면 표를 나누거나 문구를 줄인다.
- `> [팁|주의|참고|요약] 내용`은 색 박스로, `🌐 바로가기 │ 이름 │ 주소`는 링크 박스로 바뀐다. `🔗 링크`는 브랜드커넥트 제휴 링크 전용이다.
- `📷`, `🔗`, `🌐` 줄, 표, 구분선, 목차는 글자 수에서 빠진다. 곁들임 박스의 글은 글자 수에 들어간다.

## 하지 않는 것

- **경험 지어내기.** "써 보니", "제가 직접" 같은 문장은 사용자가 준 경험 메모가 있을 때만 쓴다. 지어낸 체험담은 독자를 속이는 일이고, 대가성 글에서는 표시광고법 위반 소지가 있으며, 검색 품질 평가에서도 불리하다.
- **자동 발행.** 네이버 블로그는 글쓰기 API가 막혀 있고, 자동화 도구로 올리면 계정 제재 위험이 있다. 그래서 이 봇은 붙여넣기 직전까지만 만든다.
- **같은 글 재활용.** 블로그가 달라도 같은 원고를 돌려 쓰지 않는다. 유사 문서로 묶이면 둘 다 노출이 줄어든다.
- **광고 클릭 유도.** "광고 한 번 눌러 주세요" 같은 문장은 애드포스트 약관 위반으로 수익 지급이 막힐 수 있다.

## 프로필 추가·수정

새 블로그는 `profiles/_template.md`를 복사해 채운다. 사용자가 "앞으로도 이렇게"라고 하거나 같은 수정을 두 번 요청하면, 한 글에만 해당하는지 따져 보고 프로필(블로그별 규칙)이나 참고 문서(공통 규칙)의 수정안을 제안한다.
