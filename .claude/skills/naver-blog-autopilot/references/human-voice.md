# 사람이 쓴 글로 읽히게

독자는 AI 글을 냄새로 안다. 냄새의 정체는 대부분 **정보가 없는 문장**과 **똑같은 리듬**이다. 꾸미는 표현을 더하는 게 아니라 빈 문장을 빼고 구체적인 것을 넣으면 사람 글에 가까워진다.

## 1. 쓸 때

- **답부터.** 도입 3줄 안에 결론. "오늘은 ~에 대해 알아보겠습니다"로 시작하지 않는다.
- **구체적으로.** "다양한 기능" 대신 기능 이름을, "저렴하다" 대신 금액을, "오래 간다" 대신 시간을 쓴다. 숫자를 모르면 그 문장은 뺀다.
- **판단에는 이유를.** "~하는 것이 좋습니다" 대신 "저는 ~를 권해요. ~이기 때문이에요".
- **한 문장에 정보 하나, 문단은 2~3문장.** 모바일 화면에서 한 문단이 한눈에 들어와야 한다.
- **리듬을 섞는다.** 짧은 문장 뒤에 조금 긴 문장. 같은 어미("~습니다", "~해요")가 세 번 연달아 나오면 하나를 바꾼다.
- **독자의 말로.** 제조사 용어가 아니라 검색창에 치는 말. 어려운 용어는 한 번 일상 장면에 빗대 풀어 준다.
- **다 말하지 않는다.** 상세페이지의 모든 스펙을 같은 무게로 나열하지 말고, 선택을 바꾸는 것만 남기고 "이건 몰라도 된다"를 하나 짚어 준다.
- **글마다 모양을 다르게.** 도입을 매번 같은 방식(상황 묘사 → 질문)으로 열지 않는다. 결론형, 숫자형, 흔한 오해 짚기 중에서 고른다.

## 2. 퇴고할 때 걷어낼 것

| AI 글 신호 | 고치는 법 |
| --- | --- |
| "오늘은 ~에 대해 알아보겠습니다", "~에 대해 살펴보겠습니다" | 삭제하고 결론으로 시작 |
| "결론적으로", "종합하면", "요약하자면", "마지막으로" | 삭제. 내용이 결론이면 표지가 필요 없다 |
| "~라고 할 수 있습니다", "~것으로 보입니다" 반복 | 확인한 것은 단정하고, 확인 못 한 것은 뺀다 |
| 자문자답 "왜 그럴까요? 바로 ~ 때문입니다" | 이유를 바로 쓴다 |
| "다양한", "효과적인", "완벽한", "최고의", "혁신적인" | 숫자나 상황으로 바꾸거나 삭제 |
| "첫째, 둘째, 셋째"로만 이어지는 전개 | 번호 목록으로 빼거나 문단 사이를 생각의 흐름으로 잇는다 |
| "~뿐만 아니라 ~도", "단순한 ~이 아니라 ~" | 한쪽만 말한다 |
| 모든 소제목이 같은 형태("~의 장점", "~의 단점", "~의 특징") | 질문형·조건형·서술형을 섞는다 |
| 문단마다 끝에 붙는 요약 한 줄 | 삭제 |
| "도움이 되셨길 바랍니다", "궁금한 점은 댓글로" | 독자가 답하기 쉬운 구체적인 질문 하나로 |
| 이모지 줄줄이, 느낌표 연속 | 프로필이 허용한 만큼만 |
| "~하시는 분들이 많으실 텐데요", "~하셨나요?" 도입 | 독자 상황을 한 문장으로 단정해 묘사하거나 결론으로 시작 |

`check_post.py`가 이 표의 대표 표현을 세어 준다. 스크립트가 못 잡는 것(리듬, 빈 문장)은 직접 소리 내어 읽듯 확인한다.

## 3. 경험과 근거

문장마다 넷 중 무엇인지 드러나게 쓴다.

| 구분 | 문장 모양 | 조건 |
| --- | --- | --- |
| 확인한 사실 | "제조사 안내에 따르면 ~", "공식 스토어 기준 ~원" | 출처가 있다 |
| 흔한 상황 | "~한 경우가 많아요" | 단정하지 않는다 |
| 필자 판단 | "저는 ~를 권해요. ~이기 때문이에요" | 이유가 사실에서 나온다 |
| 직접 경험 | "써 보니", "제 경우엔" | 사용자가 경험 메모를 준 경우에만 |

경험 메모가 없는 완전 자동 글에서는 직접 경험 문장을 쓰지 않는다. 대신 사람다움은 **선택과 판단**에서 만든다: 무엇을 먼저 말하는지, 무엇을 몰라도 된다고 하는지, 누구에게 무엇을 권하는지. 계산해서 보여 주는 것(전기료, 1회 사용 단가, 걸리는 시간)도 직접 써 본 것 못지않게 독창적인 정보다.
